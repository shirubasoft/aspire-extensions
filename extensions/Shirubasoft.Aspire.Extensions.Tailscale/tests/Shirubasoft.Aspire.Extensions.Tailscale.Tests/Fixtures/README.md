# Pinned Tailscale state fixtures

`tailscaled.state.v1.102.5.json` is sanitized captured state. Its private keys are zero values, and its identities and tailnet names are synthetic. `generate.go` verifies that its decoded prefs and profile metadata round-trip byte-for-byte through the pinned `ipn.PrefsFromBytes`, `Prefs.ToBytes`, and `ipn.LoginProfile` APIs.

`tailscaled.single-profile.state.v1.102.5.json` is generated offline from that fixture. It exercises optional prefs, nested Drive shares and user groups, Serve state, and the profile's route-info key. The generator uses upstream prefs and metadata serialization, then writes the store through `store.NewFileStore`. `tailscaled.multi-profile.state.v1.102.5.json` adds a second profile with different tags and is a rejection fixture.

The sidecar accepts pre-registration state containing no keys or only a machine key, and registered state containing one complete Linux profile. The compact `_profiles` map key, embedded `ID`, `Key`, `_current-profile`, and existing prefs key must agree. The map and profile ID use the four lowercase hexadecimal digits generated by pinned `newUnusedID`; `LocalUserID` is empty on Linux. Profile-scoped Serve and route-info keys must belong to that profile. Incomplete, legacy and multi-profile stores require a volume reset.

`startup_test.go` observes the real `ReadStartupPrefsForTest` lookups through `store.NewFileStore`. For each accepted fixture and CRLF prefs it asserts that startup reads exactly the checked profile, loads identical complete prefs with `tag:apps`, and preserves the store on repeated restarts. Fresh stores must load no persisted profile and remain logged out. The same checks assert that the legacy-daemon and embedded-ID redirect reproducers really load `tag:web` upstream.

`lifecycle_test.go` runs inside the pinned upstream profile-manager package. It proves that registration, restarts and re-authentication with the same or a changed tagged node identity retain one profile ID. `containerboot` invokes ordinary `tailscale up`, which updates the current profile; creating a separate profile requires the explicit new-profile path.

Generate and compare in an isolated module, from the repository root:

```bash
fixture_dir="$(realpath extensions/Shirubasoft.Aspire.Extensions.Tailscale/tests/Shirubasoft.Aspire.Extensions.Tailscale.Tests/Fixtures)"
generator_dir="$(mktemp -d)"
cd "$generator_dir"
go mod init tailscale-state-fixtures
go get tailscale.com@v1.102.5
go run -mod=mod "$fixture_dir/generate.go" \
  "$fixture_dir/tailscaled.state.v1.102.5.json" \
  "$generator_dir/tailscaled.multi-profile.state.v1.102.5.json"
cmp "$generator_dir/tailscaled.single-profile.state.v1.102.5.json" \
  "$fixture_dir/tailscaled.single-profile.state.v1.102.5.json"
cmp "$generator_dir/tailscaled.multi-profile.state.v1.102.5.json" \
  "$fixture_dir/tailscaled.multi-profile.state.v1.102.5.json"
```

The script's exact key allowlists come from the pinned JSON field names in [ipn/prefs.go](https://github.com/tailscale/tailscale/blob/v1.102.5/ipn/prefs.go#L59-L349), [types/persist/persist.go](https://github.com/tailscale/tailscale/blob/v1.102.5/types/persist/persist.go#L21-L36), [tailcfg/tailcfg.go](https://github.com/tailscale/tailscale/blob/v1.102.5/tailcfg/tailcfg.go#L289-L302), [drive/remote.go](https://github.com/tailscale/tailscale/blob/v1.102.5/drive/remote.go#L29-L49), and the Linux TPM representation in [feature/tpm/attestation.go](https://github.com/tailscale/tailscale/blob/v1.102.5/feature/tpm/attestation.go#L144-L147). The generator prints the exported types' JSON names for comparison. The TPM object's names are verified against source because generation requires hardware.

Run the startup assertions in the same isolated module:

```bash
cp "$fixture_dir/startup_test.go" "$generator_dir/"
TAILSCALE_FIXTURE_DIR="$fixture_dir" go test -mod=mod -count=1 -v
```

Run the lifecycle check in a fresh checkout of upstream v1.102.5:

```bash
upstream_dir="$(mktemp -d)"
git clone --branch v1.102.5 --depth 1 https://github.com/tailscale/tailscale.git "$upstream_dir"
cp "$fixture_dir/lifecycle_test.go" "$upstream_dir/ipn/ipnlocal/sidecar_lifecycle_test.go"
go test -C "$upstream_dir" -run '^TestSidecarSingleProfileLifecycle$' -count=1 -v ./ipn/ipnlocal
```

These checks use local synthetic state and start no daemon, connection or tailnet registration. The metadata allowlist follows [LoginProfile and NetworkProfile](https://github.com/tailscale/tailscale/blob/v1.102.5/ipn/prefs.go#L1052-L1124).

Outer keys follow [ipn/store.go](https://github.com/tailscale/tailscale/blob/v1.102.5/ipn/store.go#L24-L86), [ServeConfigKey](https://github.com/tailscale/tailscale/blob/v1.102.5/ipn/serve.go#L28-L30), [profile keys](https://github.com/tailscale/tailscale/blob/v1.102.5/ipn/ipnlocal/profiles.go#L494-L503), [debug keys](https://github.com/tailscale/tailscale/blob/v1.102.5/ipn/ipnlocal/local.go#L839-L884), and [route-info keys](https://github.com/tailscale/tailscale/blob/v1.102.5/ipn/ipnlocal/local.go#L8584-L8588). The Linux lifecycle narrows those versioned key families by excluding legacy and Windows selectors. Unknown keys, spelling variants, and case-insensitive duplicates fail closed. The literal `State schema` version and the fixture version are each checked against the image pin, so a version bump requires refreshing the schema and fixtures.
